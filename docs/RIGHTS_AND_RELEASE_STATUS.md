# Rights and release status

Status reviewed: 2026-08-08

This document records release evidence and blockers. It is not legal advice.

## Local provenance review

The supplied folder contained no Git repository, commit history, remote,
license, copyright header, contributor list, team record, rights assignment,
competition file, client/employer notice, or starter-project attribution. No
competition, hackathon, challenge, judging, award, embargo, or sponsor marker
was detected in the local files.

Absence of those records does not prove sole ownership. Before a public or
proprietary release, the creator must document who wrote or supplied the source,
templates, inline icons, geometric mark, and product specification; identify any
AI-assisted or third-party contributions; and obtain any required assignments or
permissions.

## Naming review

Primary-source checks found active software businesses using both requested
names:

- An existing product uses the exact **ArtFlow Pro** name for software serving
  artists and galleries: <https://artflow-pro.com/about-us/>.
- An existing healthcare-software business uses **Aionex**:
  <https://www.aionex.com/>.

These findings do not decide trademark rights in any jurisdiction, but they
create a material risk of confusion for a commercial software launch. Public
branding requires a qualified trademark search and clearance, or a distinct
cleared name. No affiliation or endorsement is claimed.

## Current decision

- Public GitHub release: **blocked**.
- Proprietary AIONEX copyright claim: **not applied**.
- Open-source claim: **not applied**.
- Competition disclosure: **not created**, because no competition origin was
  detected.

## Gates for public release

1. Obtain a signed creator/contributor provenance statement.
2. Resolve any team, employer, client, competition, or AI-output rights.
3. Confirm the origin and redistribution rights for the inline icon sprite,
   geometric mark, and texture.
4. Complete a qualified name/trademark clearance or adopt a cleared name.
5. Review the intended public license with the verified rightsholder.
6. Re-run secret, privacy, dependency, staged-content, and Git-history scans.
7. Re-run the complete clean-clone quality gate.

Until all gates pass, the private repository may be used for engineering review
and provenance work only.
